# NaviGo release checklist

## Product identity

- [ ] Replace `com.myplacestracker` with a permanent organization-owned Android application ID and iOS bundle ID before the first store upload. These IDs cannot be casually changed after launch.
- [ ] Confirm the final app name, support email, support URL, privacy-policy URL, category, countries, age rating, screenshots, and store descriptions.
- [ ] Review the Android adaptive/round launcher icon on real launchers and all iOS icon sizes. Android lint currently flags the round icon artwork as square/duplicated.
- [ ] Increment Android `versionCode` and iOS `CURRENT_PROJECT_VERSION` for every upload; update the public version names when appropriate.

## Privacy and legal

- [ ] Publish the completed `PRIVACY_POLICY.md` at a public HTTPS URL.
- [ ] Declare precise location and third-party service handling accurately in Google Play Data safety and App Store Connect App Privacy.
- [ ] Verify current terms, attribution, rate limits, retention, and commercial-use permission for every map, geocoder, POI, routing, and connectivity provider.
- [ ] Confirm the iOS privacy report generated by Xcode matches `PrivacyInfo.xcprivacy` and App Store Connect answers.
- [ ] Confirm export-compliance answers. The project declares that it does not use non-exempt encryption beyond platform HTTPS.

## Production infrastructure

- [ ] Replace community/public Photon, Nominatim, Overpass, OSRM, and tile endpoints with organization-controlled or contracted services before marketing at scale.
- [ ] Add crash reporting and service monitoring under organization-owned accounts, with privacy-safe redaction and release symbols/source maps.
- [ ] Define uptime/error-rate alerts, provider quotas, incident ownership, and a rollback process.
- [ ] Back up Android upload keys securely and configure Play App Signing. Never commit keys or passwords.
- [ ] Configure the Apple team, App Store signing, and provisioning in Xcode/CI.

## Verification

- [ ] Run `npm ci` on a clean checkout.
- [ ] Run `npm run verify`.
- [ ] Run `npm run android:lint` and review every warning.
- [ ] Build the signed Play bundle with `npm run build:aab` and test the Play internal-testing install.
- [ ] Archive the iOS Release build and validate it in Xcode Organizer/TestFlight.
- [ ] Test fresh install, denied/revoked permission, weak GPS, no network, slow network, provider outage, process restart, low storage, map download interruption, and navigation rerouting.
- [ ] Test supported small/large phones, tablets if listed, light/dark system modes, font scaling, screen readers, and both platform back-navigation behaviors.
- [ ] Perform real-road drives only with a second person operating the test device; verify route distance, turns, rerouting, arrival, TTS, and GPS recovery.

## Launch control

- [ ] Ship through internal testing, then a small staged rollout.
- [ ] Monitor crashes, ANRs, routing failures, search latency, map failures, and user feedback before increasing rollout.
- [ ] Keep a tested previous build available for rollback.
